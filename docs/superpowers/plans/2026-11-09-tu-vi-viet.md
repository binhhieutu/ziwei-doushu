# Tử Vi Việt Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Website tiếng Việt tính lá số theo lịch Việt Nam, luận giải và đối chiếu hai lá số qua 9Router, chạy local và có kiểm thử.

**Architecture:** Giữ Chinese identifiers và hành vi engine cũ. Thêm adapter lịch Việt, component Việt và API máy chủ với SSE chuẩn hóa; các lane không ghi đè file của nhau. Root tích hợp và chạy release checks, reviewer độc lập kiểm tra correctness/security.

**Tech Stack:** Next.js16.4.5, React19, TypeScript, iztro, lunar-javascript, adapter Vietnamese lunar dependency đã kiểm tra, Zod, Vitest/V8 coverage và Playwright.

**Spec:** `docs/superpowers/specs/2026-11-09-tu-vi-viet-design.md` — đã được người dùng duyệt, tự quyết chi tiết và tiếp tục không hỏi giữa các task.

## Global Constraints

- Năm đầu vào mới 1900–2050; UTC+7, giờ dân sự mặc định; trường hợp không biết giờ phải có giờ giả định rõ.
- Không sửa Chinese IDs thành Vietnamese IDs; không đổi mặc định của engine/các helper cũ.
- Bí mật chỉ ở biến môi trường máy chủ và `.env.local` được ignore; không ghi log birth/conversation/key.
- AI chỉ chạy bằng hành động chủ động; server không nhận baseURL/model/system prompt từ client.
- Tối thiểu 80% coverage trên logic mới/thay đổi có thể thực thi; unit/integration/E2E và upstream regressions đều cần.
- Giữ license/attribution; cổ văn là nguyên văn chữ Hán; không mặc nhận đã dịch toàn văn.
- Bản giao local; không push/deploy khi chưa được yêu cầu thêm.

## Review Focus

- 17/02/2007 phải là 01/01 âm Việt Nam, và không tái dùng ngày dân sự Trung Quốc làm ngày sinh thật.
- Không rõ giờ, giờ Tý và đổi ngày/tháng/năm phải có metadata nhất quán giữa form, bảng số và AI.
- Model stream chia ở bất kỳ byte UTF-8 nào, lỗi/timeout/hủy phải dọn upstream và slot concurrency.
- Chart giả/malformed body, hội thoại quá dài, request lặp và endpoint/model tự chọn phải bị từ chối trước gọi provider.
- Mobile không ép dài tên sao thành tràn layout; chọn cung và đổi hạn không được gọi AI ngầm.

### Task 2: Bounded server AI and normalized streaming

**Owner/files:** backend agent: `lib/ai/*`, `app/api/interpret/route.ts`, `app/api/heming/route.ts`, `tests/ai-*.test.ts`.

**Interfaces:**

- POST interpret: `{birth:VietnamBirthInput,messages?:{role:'user'|'assistant',content:string}[],topic?:'overview'|'career'|'relationships'|'wealth'|'health'|'palace',palaceBranch?:number,view?:VietnamChartView}`.
- POST heming: `{birthA:VietnamBirthInput,birthB:VietnamBirthInput,messages?:{role:'user'|'assistant',content:string}[],question?:string}`.
- Both return SSE `data: {"delta":{"text":"..."}}\n\n`, terminal `[DONE]`, error event safe message; HTTP JSON errors before stream `{error:string,code:string}`.
- Server env: `AI_BASE_URL`, `AI_API_KEY`, `AI_MODEL`, optional bounds. 9Router local base `http://127.0.0.1:20128/v1`. No secret passed to client.
- Display adapter supplied by root: `lib/i18n/vi.ts`: `viLabel(string):string`, `canChiLabel(string):string`.

- [x] RED unit/integration: validation/caps, forged chart ignored/rejected, missing settings, provider errors, SSE UTF8 fragmentation, cancel/timeout, limiter release/global cap.
- [x] Implement schemas, canonical chart recomputation, Vietnamese prompt/context, fixed configured destination, streaming normalization and resource caps.
